# Памятка для ИИ-агентов и тех, кто дорабатывает карту

Этот файл для тех, кто продолжает работу над общей картой GammaOS Next +
dArkOS для AISLPC RG52 Mini (RK3562), в том числе с помощью ИИ-агента: Claude
Code, Codex, Cursor и подобных. Здесь собрано то, чего не видно из кода
сразу: правила проекта, вещи, которые ломаются незаметно, и уже отвергнутые
идеи. Как устроена карта — [doc/01-устройство.md](doc/01-устройство.md), как
её собрать — [doc/02-сборка.md](doc/02-сборка.md).

Агенту: прочитай этот файл и `doc/01-устройство.md` целиком до первой правки.

## 2. Как присылать правки

- **Работа идёт в форке и приходит Pull Request-ом в `main`.** Прямо в `main`
  пишет только владелец.
- Один PR — одна тема. В описании: что было не так, почему так чинится,
  **как проверено** — на какой ревизии платы (A или B), на общей карте или
  на одиночной, какие версии систем; и что не проверено.
- Документация, описания выпусков и сообщения коммитов — по-русски, как в
  истории. Надписи на экране устройства (кадры меню) — по-английски.
- Файлы в LF. Историю не переписывать: без `push --force` в `main`.
- В документах — ссылки только на репозитории проекта (таблица выше) и на
  то, что нужно для сборки. Двоичные блобы производителя (rkbin, vendor,
  idbloader) в репозиторий не класть: сборщик берёт их из образов систем.

## 3. Выпуски

- **Выпуски публикует только владелец** (mamaich). Образы карты, тома и
  `SHA256SUMS` в PR не присылать.
- **Номер выпуска карты = номер dArkOS в ней.** GammaOS берётся последняя на
  момент сборки.
- Новый образ карты — только при крупных изменениях: обе системы
  обновляются по воздуху и на старой карте, перезаписывать её ради новых
  версий не нужно.
- Образ около 17 ГиБ, в выпуск идёт архив 7z томами по 1950 МиБ
  (`7zz a -mx=5 -v1950m`, лимит вложения GitHub — 2 ГиБ) и `SHA256SUMS` с
  суммами томов и самого `.img`. Перед публикацией архив распаковывается и
  сверяется с суммой образа, после загрузки — digest каждого вложения.
- Описание выпуска — `doc/release-vX.Y.md` по образцу прошлых: таблица (тома,
  размеры, sha256, версии GammaOS, dArkOS и загрузчика), «Как записать»,
  «Переход с прежних выпусков», «Что нового» по системам. На GitHub тело
  выпуска — тот же файл с абзацами в одну строку и относительными ссылками на
  `blob/main/doc/`.

## 4. Инварианты: ломается незаметно

- **Загрузочный флаг (LegacyBIOSBootable) — только у p3.** С первого такого
  раздела загрузчик берёт своё дерево устройств, логотип, картинки зарядки и
  кадры меню. У FAT GammaOS (p5) флага быть не должно.
- **Номера p3 и p4 — за dArkOS.** Она обращается к ним по номерам
  (`mmcblk1p3/p4` в fstab и initrd). Android ищет разделы только по именам,
  поэтому у его разделов номера любые.
- **FAT GammaOS называется `dArkOS_Fat`** — это имя пишет OTA GammaOS. На
  карте с одной GammaOS раздел называется так же.
- **`userdata` (p9) — физически последний.** Его растягивает до конца карты
  служба GammaOS, и она жёстко работает с p9. В образе `userdata` — нули:
  форматирует его сам Android при первом запуске.
- **Загрузчик в p1 — тот же, что в текущем выпуске GammaOS** (сравнивать
  sha256 с разделом `uboot` её образа). OTA GammaOS пишет раздел `uboot` по
  имени, и любой другой загрузчик на карте при её обновлении молча
  заменится. Загрузчик без меню на общей карте грузит только dArkOS.
- **Что сборщик кладёт на FAT dArkOS (p3)** — десять `bootmenu*_*.bmp` и пустой
  `/dualboot` (по нему dArkOS узнаёт общую карту). OTA dArkOS обязана их
  сохранить. Кадры меню — BMP 8 бит RLE8, повёрнуты на 90° (панель портретная,
  720x1280), около 50 КБ: другого формата загрузчик не покажет.
- **Файлы с p3, которые загрузчик читает при любом выборе**:
  `rk3562-rg52mini.dtb`, `logo.bmp`, `battery_*.bmp`. По этому дереву он
  поднимает дисплей и кнопки меню (`/play_joystick`, `adc-keys`,
  `saradc@ffaa0000`), так что dArkOS не может менять эти узлы несовместимо.
  Подменять этот dtb «под GammaOS» нельзя: ядро dArkOS берёт тот же файл.
- **Ловушка с деревом устройства.** Живое дерево загрузчика (OF_LIVE) строится
  из dtb с p3, лежащего по `fdt_addr_r` (0x08300000), и имена и значения его
  свойств указывают прямо в этот блоб. `sysboot` GammaOS грузит свой dtb с p5
  по тому же адресу. Всё, что загрузчик впервые читает из дерева после этого,
  читает мусор. Так на платах первой ревизии терялась пометка об отсутствии
  контроллера Type-C, и экран в GammaOS оставался чёрным (исправлено в
  `rg52mini-1.6`). На одиночной карте и в dArkOS файл тот же, поэтому
  поломка видна только на общей карте и только в GammaOS. Правило: **после
  загрузки дерева для ядра загрузчик ничего не опрашивает и не читает из своего
  дерева**, опрос железа — в `rk_board_init()` с запоминанием результата.
- **Первый запуск — без меню.** Пока на `dArkOS_Fat` нет файла
  `bootmenu_ready` (его ведёт служба GammaOS по `/data/setupcompleted`), карта
  сразу грузит GammaOS: `userdata` ещё не отформатирован, а папку ROMs
  раскладывает мастер настройки. dArkOS до этого ничего в ROMs не пишет.
- **Права в ROMs.** Ромы лежат в `userdata` Android (`media/0/ROMs`), группа
  `media_rw` (1023), setgid и ACL по умолчанию. `chmod` без группы, `cp -p` и
  `rsync -a` сужают права, и Android теряет запись.
- **Выбор в меню** хранится в хранилище Rockchip на карте (сектор 7168 и
  дальше, идентификатор `0x5242`). Сборщик копирует сектора 34..16383 из образа
  GammaOS (`--head`), запись образа выбор сбрасывает.

## 5. Как проверять

- Сборка — в Linux или WSL, без root, на родной файловой системе Linux (на
  `/mnt/c` в разы медленнее): `python3 -I mk-dualboot.py --gamma … --darkos …
  --uboot …`. В конце сборщик сам показывает таблицу разделов и содержимое
  обоих FAT — посмотри на них.
- Таблица разделов готового образа: `sgdisk -p` и `sgdisk -i 3` / `-i 5`
  (атрибуты: у p3 — бит 2, у p5 — ноль).
- На консоли: в dArkOS — `ssh`, в GammaOS — `adb`.
  `/proc/device-tree/chosen/rg52,typec-probe` показывает итог опроса Type-C
  загрузчиком: `00 00 00 01 …` — вторая ревизия, `00 00 00 00 …` — первая. Если
  свойства нет, загрузчик старше 1.6 или фиксапы дерева не выполнились.
- Плат две ревизии: A (без контроллера Type-C HUSB311, Wi-Fi RK915) и B. У
  владельца только B, первая есть у пользователей. Проверки у пользователей
  — только при подтверждённой поломке и одним образом, который сразу
  показывает ответ; тестовые образы «на всякий случай» не рассылать.
- Обновления по воздуху обеих систем проверяются на общей карте: OTA GammaOS
  переписывает `system`, `vendor`, `dArkOS_Fat` и `uboot`; OTA dArkOS — файлы
  на p3 и `rootfs`, не трогая загрузчик, разметку и разделы GammaOS.

## 6. Что уже обсуждено и отвергнуто

- **Отдельный раздел для ромов.** Не нужен: dArkOS монтирует `userdata`
  Android и берёт `media/0/ROMs`, обе системы видят одни игры.
- **Два загрузочных раздела** (p3 и p5). Ломали чтение файлов загрузчиком;
  загрузчик это теперь переживает, но флаг держим один.
- **Перезагрузка после выбора в меню** (флаг в регистре режима загрузки и
  ранний dtb с раздела выбранной системы). Обходит ловушку с деревом целиком,
  но стоит +4–5 с и двойной логотип на каждой загрузке GammaOS и требует правок
  зарядки. Не нужна, пока соблюдается правило из п. 4; вернуться к ней — только
  если появится поздний опрос, без которого не обойтись.
- **Другой `fdt_addr_r` для `sysboot` GammaOS** как страховка. Других
  читателей дерева после загрузки dtb ядра нет (проверено по коду: RNG,
  фиксапы дисплея, remove-методы драйверов), поэтому без нужды не делали.
